# 06 - Badcase 分析与模型优化方法论

## 核心结论

- **高置信度错误（>0.9）是最危险的**，代表系统性问题（标注错误或未见过的样本），优先排查
- **低置信度错误（~0.5）是边界案例**，网络自己也不确定，可用拒识机制处理
- 优化收益顺序：修复错误标注 > 补充数据 > 数据增强 > 调整模型结构
- **不可约误差（Bayes error）真实存在**：剩余错误中有些连人类也会认错，无法通过优化消除
- 99% → 99.5% 的难度远大于 95% → 99%，到高准确率阶段要判断投入是否值得

## ❓ 训练测试完成后，如何把 badcase 导出来定位问题？

见配套代码 `mnist-demo/export_badcases.py`，训练后执行：

```bash
python3 train_cnn.py      # 训练并保存模型（cnn_model.pth）
python3 export_badcases.py  # 导出所有预测错误的样本
```

输出结构：
```
badcases/
├── true_4/pred_9/    ← 真是4，被认成9的图片
├── true_7/pred_1/    ← 真是7，被认成1的图片
└── badcases.csv      ← index, true_label, pred_label, confidence, image_path
```

## ❓ confidence 有 0.9 以上的，也有 0.5 左右的，应该用什么方案分别优化？

两种错误根因不同，优化方向也不同。

### 高置信度错误（confidence > 0.9）——最危险

**含义**：网络非常确信自己是对的，但实际错了。系统性问题。

常见根因：
- 训练集有**错误标注**（一批"4"被标成了"9"）
- 这种写法的样本训练集里从未出现过
- 模型结构对某两类特征区分不足

优化方向：
1. 人工检查这批图片，确认标注是否正确
2. 针对这类混淆，定向补充训练数据
3. 数据增强，让模型见过更多变体

### 低置信度错误（confidence 0.4~0.6）——边界案例

**含义**：网络自己也不确定，只是押错了。

常见根因：
- 图片本身质量差（模糊、残缺）
- 边界样本：人类也可能认错

优化方向：
1. 数据增强，加强在模糊区域的训练
2. 引入**拒识机制**：confidence < 阈值时不输出，交人工审核

## 全局优化框架

```
Step 1: 诊断根因
  → 区分高置信度 vs 低置信度错误
  → 找出出错最多的混淆对（如 4→9，7→1）

Step 2: 数据层面优化（收益最大）
  → 修复错误标注
  → 数据增强（旋转、缩放、加噪声）
  → 补充稀缺类别的样本

Step 3: 模型层面优化
  → 加深网络
  → 调整学习率 / 训练轮数
  → 更换更强的架构

Step 4: 后处理优化
  → 低置信度样本拒识
  → 集成多个模型投票
```

## 优化优先级

| 优先级 | 动作 | 预期收益 |
|---|---|---|
| ★★★ | 分析高置信错误，排查标注问题 | 消除系统性错误 |
| ★★★ | 针对出错最多的混淆对补充数据 | 直接提升该类准确率 |
| ★★☆ | 数据增强（旋转±15°、随机噪声）| 全局 +0.1~0.3% |
| ★★☆ | 训练更多轮 + 学习率衰减 | 让模型充分收敛 |
| ★☆☆ | 更换更深的网络架构 | 边际收益递减 |

## 关键认知：不可约误差

**99% → 99.5% 的难度远大于 95% → 99%。**

剩余错误中有相当一部分是人类也会认错的样本（字迹本身含糊）。这是"不可约误差（Bayes error）"，无法通过优化模型消除。到这个阶段需要判断：继续投入的收益是否值得。
