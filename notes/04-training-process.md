# 04 - 训练流程：损失函数、优化器、反向传播

## 核心结论

- 一次训练最小单元：`zero_grad` → 前向传播 → 计算损失 → `backward` → `step`，循环几万次参数收敛
- **损失就是"错了多少"的量化**，越小越好；CrossEntropyLoss = `-log(正确类别的预测概率)`
- 简单波动（小于 0.5%）是正常随机性，不是过拟合；过拟合 = 训练损失下降但测试准确率持续下滑
- `zero_grad` 必须有，否则 PyTorch 会累加梯度，导致参数更新方向错误
- **Adam 优化器**比 SGD 收敛更快，对学习率不敏感，是首选默认优化器

---

## ❓ 每轮输出的损失值是什么，怎么算出来的？

**损失值是"网络当前有多错"的量化数字，越小越好，0 是理论下限。**

典型训练输出：
```
Epoch 1  损失: 0.2136  测试准确率: 98.45%
Epoch 2  损失: 0.0847  测试准确率: 98.77%
...
```

损失从大到小，说明网络在持续学习变准。

### CrossEntropyLoss 的计算过程

网络输出 10 个原始分数 → Softmax 转概率 → 取正确类别的概率 → 取负对数：

```
loss = -log(正确类别的预测概率)
```

| 正确类别概率 | 损失值 | 含义 |
|---|---|---|
| 99% | 0.01 | 非常确信且正确 |
| 50% | 0.69 | 随机猜 |
| 10% | 2.30 | 猜错了 |
| 1%  | 4.60 | 严重猜错 |

越自信地犯错，惩罚越重（非线性）。

代码里输出的是**一轮所有 batch 的平均损失**：

```python
total_loss / len(train_loader)
```

## ❓ Epoch 4 相比 Epoch 3 损失变小但测试准确率下降，是过拟合吗？

**不是过拟合，是正常的随机波动。**

测试集有 10000 张图，准确率差 0.11% = 只差 11 张图的判断。这 11 张可能这轮刚好判断错了，下轮又对了，是正常的随机性。

**过拟合的样子**（需要担心的是这种）：

```
          过拟合特征：训练损失持续下降 + 测试准确率持续下滑

训练损失:   0.21 → 0.08 → 0.03 → 0.01  持续下降
测试准确率: 98%  → 99%  → 98%  → 95%   ← 持续下滑，不是波动
```

**判断标准**：

| 现象 | 原因 | 需要处理？ |
|---|---|---|
| 测试准确率小幅上下波动 | 随机性，正常 | 否 |
| 测试准确率整体稳定/缓慢上升 | 正常收敛 | 否 |
| 训练损失降，测试准确率**持续**下滑 | 过拟合 | 是 |
| 训练损失不降，准确率也不涨 | 欠拟合 | 是 |

## ❓ optimizer 是什么？zero_grad() 和 step() 是什么意思？

**Optimizer（优化器）**：根据梯度更新网络参数的算法。

### 梯度是什么

`loss.backward()` 计算出：每个参数变化一点点，损失会怎么变化。

```
梯度 > 0：参数增大 → 损失增大 → 应该减小参数
梯度 < 0：参数增大 → 损失减小 → 应该增大参数
```

参数应沿梯度反方向移动，这就是"梯度下降"。

### optimizer.step()

执行一次参数更新：

```
新参数 = 旧参数 - 学习率 × 梯度
```

### optimizer.zero_grad()

清空上一次计算留下的梯度。

PyTorch 默认**累加梯度**，不清零的话第二个 batch 会混入第一个 batch 的残留，导致更新方向错误：

```
不清零：batch2 实际使用的梯度 = batch1残留 + batch2新梯度  ← 方向错误
```

### 为什么用 Adam 而不是 SGD

最基础的 SGD：`新参数 = 旧参数 - lr × 梯度`

Adam 的两个改进：
- **自适应学习率**：更新频繁的参数步子变小，稀疏的参数步子变大
- **动量**：利用历史梯度，让方向更平稳，不容易震荡

实际效果：收敛更快，对学习率选择不那么敏感。

## 一次训练的完整 5 步循环

```python
optimizer.zero_grad()                    # 1. 清空上次梯度
outputs = model(images)                  # 2. 前向传播
loss = loss_fn(outputs, labels)          # 3. 计算损失
loss.backward()                          # 4. 反向传播（计算梯度）
optimizer.step()                         # 5. 更新参数
```

每个 batch 重复一次，训练几万次后参数收敛。
